1. fgets() reads tests.txt one line at a time so test_runner can process each command separately.

2. Each command must be parsed into an argument array because execvp() needs the command + arguments in an array of strings and ending with null.

3. fork() will return -1 if it fails, 0 if in the child process and the child's process ID in the parent process.

4. When execvp() is successful, the child process runs the new program and replaces its previous program. It will not return unless an error will happen.

5. The parent calls wait() so the current test can finish before the next test would begin, making sure our tests execute in order.

6. test_runner.c checks child's exit status and if the status is 0 the test passes, if the status is not zero the test fails.

7. If a test program cannot be executed, test_runner prints an error and marks the test as a fail. It should continue to the next test so the next test commands can still run.

8. If the parent had launched all tests without waiting for them to complete, the tests could run at the same time and interfere with each other. This could cause weird outputs, incorrect test results or resource conflicts.
